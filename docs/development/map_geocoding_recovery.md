# 重复定位修复与验证

适用版本：Qt 6.2.4 / C++17；覆盖 `MapBridge.geocodeAddress` 和
`MapGeoService.requestAddressGeocode` 两个入口。

## 已确认的问题与修复

- HTTP 403 曾被一律标成“配额或并发超限”，且 4xx 错误体没有被解析。
  现在区分访问拒绝、鉴权失败、短时限流和日额度，并保留安全的数字状态码。
  不再无条件提示“检查地址和 Key”。
- 重复提交相同地址会重复发 HTTP 请求。现在同一服务实例内合并在途请求，
  每位调用方仍得到独立 requestId 和一次异步结果。
- 成功解析过的地址在进程内最多保存 32 条、5 分钟；再次使用不重复请求。
  只缓存经过经纬度验证的真实成功结果，不缓存失败、不持久化、不把旧地址
  的坐标当成新地址的结果。缓存不能修复鉴权或网络故障。
- 地址解析遇到 status 120 或 HTTP 429，最多延迟重试一次（至少 1.1 秒）；
  Retry-After 为 0～5 秒时遵守该值且至少等待 1.1 秒，较长或日期值不自动重试。
  status 121、鉴权失败及未知 HTTP 403 不自动重试。
- 成功、失败、超时都释放在途状态，之后可以再次提交；页面仍过滤过期 requestId。
- 导航页的手动起点优先于旧 IP 定位响应；坐标输入会使旧地址解析失效。
  回车与按钮共用同一保护入口；响应使用提交时的地址文本，不误用尚未提交的新输入。
  地址失败后清理 pending 状态，并显示具体错误。

## 验证边界

用户反馈“首次成功，后续同地址也失败”，并确认不是 Key 日额度耗尽，
且不进入导航页也会失败。因此导航页的状态修复不是这次反馈的已确认根因。
目前没有该失败请求的实际 HTTP/业务状态码，不能仅凭旧版红字断言其根因。
本补丁修复可由代码和本地假服务器复现的上述缺陷；真实服务端拒绝是否消失，
仍需在原运行环境复测。不得将缓存命中或测试通过描述成真实接口故障已被证实修复。

## 自动化回归（不使用真实 Key）

```bash
ctest --test-dir build --output-on-failure \
  -R '^(map_geo_service|qml_map_bridge|map_geocoding_recovery|qml_station_interactions)$'
```

覆盖首次成功→第二地址失败→原地址复用→新地址恢复、并发重复提交、两个接口的
requestId 分发、限流退避和重试上限、403 业务体分类、超时后重试、错误不缓存、
无效坐标/过长地址、错误文案不泄漏 Key/SK/sig、导航页旧回调失效和地址文本快照。

## 原环境验收

1. 重新构建、停止旧客户端，再运行修复分支；无需更改 Key 或购买额度。
2. 定位地址 A；不进导航，换地址 B，再换回 A。
3. 进入导航，返回后再定位地址 C；连续按回车/点击时不应重复发同地址请求。
4. 请求尚未结束时修改输入、或改用坐标，确认旧响应不覆盖新起点。
5. 若仍失败，仅提供界面的 `[HTTP ...] [status ...]` 及操作顺序。
   不要提供密钥、完整请求 URL 或带环境变量的日志。

新地址若真实被腾讯/代理拒绝，必须显示错误，不能用模拟定位掩盖。
