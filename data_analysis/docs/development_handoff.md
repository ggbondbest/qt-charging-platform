# 五人开发交接建议

本次 PR 交付共同的数据与清洗基础，不代替五人的后续任务。
目录统一为 `data_analysis`（下划线，不使用带空格名称），不改变一期 Qt 接口。

| 负责人 | 主要目录 | 后续交付与边界 |
| --- | --- | --- |
| 组长（你） | backend/、共享接口、核心统计口径 | 查询与预测 API、聚合读取、批次管理、随机森林主链路、联调；负责较多核心代码 |
| 成员二 | charging_data/、spark_jobs/ | 数据校验、新增清洗、HDFS上传/读写验证，维护数据字典 |
| 成员三 | ml/ | 特征工程、LSTM与基线对比、异常检测扩展、时间切分与评估 |
| 成员四 | frontend/ 的大屏和运营页 | Vue布局、地图、ECharts、筛选与空状态；只读取聚合接口 |
| 成员五 | frontend/ 的预测/质量页、测试 | 输入校验、预测曲线、清洗过程展示、验收与演示材料 |

先冻结 dataset_id、字段和 API JSON 示例再并行，不要两个人同时改共享schema。
新字段由负责同学提 PR，同步生成器、校验器、Spark与测试；生成规则变化使用新数据版本。
不得将新旧批次混在同一个 raw 表目录，也不得用样例CSV代替全量清洗结果。

## 四天推进（沿用计划书的节奏）

1. 第一天：每人跑小样本校验；数据同学在目标 Linux 验证 HDFS；组长定查询/预测接口；前端定页面。
2. 第二天：跑通真实统计→API→Vue主屏；模型完成基线与第一版树模型；质量页展示真实清洗报告。
3. 第三天：全量清洗；负荷预测网页闭环；LSTM对比、异常筛查按余量推进。
4. 第四天：冻结字段和功能，Linux复现、对账、性能/异常测试、录屏与交付；不再堆未验证扩展。

## 数据阶段验收录制顺序

1. 展示 manifest：23类、5城25站75桩、180天、完整行数；打开几张 preview 说明不同内容。
2. 小样本现场生成→校验；全量可提前完成，展示批次和校验结果，不必现场等待。
3. 展示原始脏会话与注入清单，真实运行 Spark，查看隔离原因、规范化与去重数量。
4. 展示 HDFS 实际目录和读写命令结果；普通本地目录不算 HDFS 验收。
5. 对比 Python参考与Spark小时/日报；解释金额、Wh、UTC/上海时间以及防止重复统计。
6. 后续网页完成后，再展示大屏与模型预测。当前 PR 不应演示成已经实现网页/模型。
