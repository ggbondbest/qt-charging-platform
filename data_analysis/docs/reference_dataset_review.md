# 参考数据集审查记录

审查日期：2026-09-12。范围是用户提供的 `04.数据集最终版` 中三份 CSV。只读分析，未修改或复制原文件到本仓库，也未公布其中的用户标识记录。它们仅用于了解可能的数据种类；新数据由本项目生成器独立生成。

## 1. 文件结构和数量

| 文件 | 数据行数（不含表头） | 字段数 | 观察到的粒度 | 大小 |
| --- | ---: | ---: | --- | ---: |
| `nvv2t.csv` | 3,395 | 22 | 充电会话，`sessionId` 唯一 | 420,477 字节 |
| `nvv2t_md_end.csv` | 105 | 8 | 按 `stationId` 标识的元数据记录 | 13,018 字节 |
| `dsv13r2.csv` | 1,594 | 11 | 电池记录，`esd` 每行不同 | 102,279 字节 |

三文件均可按 UTF-8 读取。每行字段数与表头一致，没有空字符串字段，没有整行重复。无空字段并不等于业务数据没有质量问题。

### 会话字段

`sessionId`, `kwhTotal`, `charging_fees`, `created`, `ended`, `startTime`, `endTime`, `chargeTimeHrs`, `weekday`, `platform`, `userId`, `stationId`, `locationId`, `managerVehicle`, `facilityType`, `Mon`, `Tues`, `Wed`, `Thurs`, `Fri`, `Sat`, `Sun`。

它提供电量、费用、时长、星期、来源平台和设施类别，可借鉴“交易事实 + 时间特征 + 场所维度”的组织方式。

### 站点元数据字段

`stationId`, `locationId`, `facilityType`, `station_name`, `address`, `device_count`, `open_time`, `update_time`。

同一 `locationId` 可以有多个 `stationId`，两者不能直接视为同一个主键。105 个 `stationId`、25 个 `locationId`，没有经纬度、城市外键和逐枪设备维表，无法仅据名字断定 stationId 是物理站点还是充电设备。

### 电池字段

`esd`, `record_time`, `soc`, `pack_voltage (V)`, `charge_current (A)`, `max_cell_voltage (V)`, `min_cell_voltage (V)`, `max_temperature (℃)`, `min_temperature (℃)`, `available_energy (kw)`, `available_capacity (Ah)`。

这些字段启发新增带明确会话外键的 SOC、电压、电流和温度样本，但不复用原始样本，也不据此声称能完成真实电池安全诊断。

## 2. 外键与完整性检查

| 检查项 | 结果 | 解释 |
| --- | --- | --- |
| 会话 `sessionId` 是否唯一 | 3,395 个唯一值，重复 0 | 可作会话主键 |
| 元数据 `stationId` 是否唯一 | 105 个唯一值，重复 0 | 可作这份元数据的主键 |
| 会话 `stationId` 是否存在于元数据 | 缺失 0 行 | 单键 join 可匹配 |
| 会话 `locationId` 是否存在于元数据 | 缺失 0 行 | 不意味着 locationId 本身唯一 |
| 会话 `(stationId, locationId)` 联合关系是否匹配 | 缺失 0 行 | 避免单独按 locationId 关联造成放大 |
| 会话与元数据 `facilityType` 是否一致 | 不一致 0 行 | 该字段可用于分组 |
| 电池记录是否能关联会话 / 站点 | 无明确对应外键 | 不应把三文件按行号拼接为一套连贯充电过程 |
| 用户维表是否存在 | 没有；会话中有 85 个去重用户标识 | 无法据此得出注册、会员、车辆电池容量等属性 |

`device_count` 的数值范围为 1–40，逐行求和得到 562，但没有足够字典说明它是该 stationId 的设备数还是 locationId 的场地总数；同一 locationId 下也存在不同 device_count。因此不将 562 当作已经核实的物理电桩总数。

## 3. 时间和数值问题

### 3.1 会话年份存在歧义

`created` 的年份原文为 `0014`（23 行）或 `0015`（3,372 行）；`ended` 使用同类格式。常规 pandas 纳秒时间类型解析这 3,395 行均会失败。Python 的 datetime 可以按公元 14/15 年解析，但那显然不是可直接用于现代充电业务的时间范围。

如果仅作为检查假设，将年份加 2,000，则会话开始范围是 2014-11-18 15:01:17 至 2015-10-04 12:44:59，涵盖 238 个有会话的日期。但来源未提供可验证的原始年份说明，因此这不是本次正式修复结果，也不作为新数据的日期依据。星期一致性不能证明这个假设，因为公历 2,000 年相差 5 个 400 年周期。

在不改变原年份的情况下，起止时差与 `chargeTimeHrs` 一致，最大误差约 0.000016 秒；没有结束早于开始的会话。`startTime`、`endTime` 与小时字段匹配；星期 one-hot 每行恰好一个 1，且与原年份星期匹配。有 1 条时长超过 24 小时，最长约 55.24 小时，可能是长时间插枪而非持续供电，需要业务定义，不能直接删除。

### 3.2 电池时间戳不可用于连续序列

1,594 条 `record_time` 的原始字符串全部是 `2.02E+13`，只有 1 个去重值；展开为 `20200000000000` 也不构成有效年月日时分秒。仅凭这份 CSV 无法恢复真实采样间隔和先后时间，不能用于“按时间预测未来 SOC”或与会话时间关联。可能曾发生精度损失，但本次无法确认原因。

### 3.3 费用和电量不能直接当经营事实

- 55 条会话 `kwhTotal=0`，没有失败状态或停机原因，不能判断是启动失败、取消、测量缺失还是确实无电量。
- 3,016 条 `charging_fees=0`，占约 88.84%。它可能是免费使用、计费规则或缺失的表达，不能推断该项目应有相同免费比例。
- 未提供费用币种、收费项、支付状态、退款、分时价格或成本，不能将该字段直接命名为人民币实收营收。
- 会话电量范围是 0–23.68 kWh。没有关联的逐时功率或车辆电池容量，不能独立验证电量与功率积分、SOC 增量是否一致。

### 3.4 电池单位和符号需先定义

- `charge_current (A)` 全部为负，范围约 -73.80002 至 -22.5 A。它可能采用充电为负的电池电流约定，不能把所有负值一律当坏数据。
- `available_energy (kw)` 同时使用“energy”与功率单位“kw”，语义不清。不能擅自当成 kWh 或据此计算电费。
- SOC 范围 15.2–75.6，最高/最低单体电压、最高/最低温度的大小关系均正确。该检查只证明局部约束成立，不证明传感器来源、校准或安全阈值有效。

元数据 `update_time` 只有一个日期值 2019/7/26，且无法作为所有历史会话当时的设施状态。三文件均没有时区说明；不能直接按中国时区重标。

## 4. 对新数据集的具体启发

| 参考文件中值得借鉴的内容 | 新数据集的做法 |
| --- | --- |
| 交易、电站、电池数据种类不同 | 扩展为维度、行为事实、运行时序、外部场景、运维事件等 23 类数据，各自明确主键、外键和粒度 |
| 星期和小时可产生运营统计 | 使用有效 UTC 时间并明确上海业务时区，时间特征从时间戳派生，避免手填多份相互矛盾字段 |
| 场所、平台、设施类型能分组 | 独立城市、站点类型、用户来源、车辆类型、设备类型维度，形成可解释差异 |
| 有原始测量可做清洗 | 单独设计重复、空值、越界、错误关联等可追溯脏数据，并保留注入清单用于验收 |
| 有费用、但缺少完整资金链 | 新增明确单位的费用分项、`PAYMENT`/`REFUND` 事件及 `SUCCESS`/`FAILED` 状态、购电量与交付电量、分时购电成本和日常/维修成本 |
| 无排队、失败和停机数据 | 新增到访请求结果、预约、队列结局、空闲资源自动故障停用、维修时间轴及评价。每次到访仅记录一次请求，不用于宣称电气握手或首次重试成功率；未模拟充电中的故障中断 |
| 电池样本无对应订单和可用时间 | 每条新电池样本明确 `session_id`、`charger_id`、`recorded_at`；仅在充电期间产生，定义充电电流为非负，能与充电过程关联 |

本仓库不分发用户提供的原始 CSV，其授权、来源和隐私属性均未得到完整证明。模拟用户使用独立合成标识，不复制参考文件的 userId、地址、会话或电池测量行。v2 从参考文件发布匿名聚合，用于办公/校园原型的小时曲线、补能量与连接时长联合抽样；不能因此声称已确认这些源站点的场所类型。价格、行为影响系数和故障概率仍为教学参数。天气另接入带署名的 ERA5 再分析缓存，不再全部随机生成。详细来源、参数和限制见 [行为依据](behavior_evidence.md)。

新数据中的维修工单代表空闲资源自动发现故障后建单并立即停用，与一期“用户报障后由管理员核实是否停用”的业务不同。停止原因仅含用户停止、时长限制、目标达成；降功率、提前结束和温升标签用于算法实验，不代表发生了自动保护或真实硬件故障诊断。

## 5. 审查方法

使用 Python 标准库 `csv`、`datetime` 和 pandas 执行全量只读检查：字段数量、空值、行重复、主键唯一性、关系 join、年份模式、起止时差、小时/星期一致性以及数值区间。统计不依赖截取几行样例；没有执行原文件内的任何指令或覆盖原文件。
