# 从运营问题反推数据集

本文件说明第二阶段为什么生成这些数据，以及大屏和预测模块可以计算什么。它是数据契约和指标设计，不表示这里列出的全部网页或模型已经实现。数据均为教学模拟数据，不代表真实城市、电站或用户经营状况。

## 1. 调研结论

充电平台管理员不只关心“有多少订单”，还关心下面五类问题。

| 管理者的问题 | 研究依据 | 本项目的设计选择 |
| --- | --- | --- |
| 哪些站真正有收益，收入是否覆盖电费和运维？ | 美国能源部 AFDC 将电费、维护、网络费用、收费方式和利用率列为运营管理重点。 | 分开保存订单费用、支付及退款、分时购电价格、日常成本和维修成本。不能把充值或未支付订单当现金收入。 |
| 哪些站太空，哪些站太拥挤，是否需要调整资源？ | 基于 27,800 处设施的原始研究同时分析电量、到达时间、占用和盈利，说明只看电站总数不够。 | 保存逐桩状态时序、充电开始/结束/拔枪时刻、站点类型、额定功率，按城市、站点和时段比较。 |
| 桩在线了，用户是否真的能充上电？ | ChargeX 的落地 KPI 包括启动成功率、启动耗时、结束成功率和会话成功率。 | 除成功充电订单，还保留充电请求未成功原因、支付失败与评论。当前事件粒度是一次到访请求，能计算到访转化与总等待，不能直接等同于电气握手启动指标。`online=1` 不等于用户成功充电。 |
| 排队多久，多少人放弃，叫号是否有效？ | 排队研究明确区分“不加入队列”和“加入后退出”，并分析等待信息与服务质量的关系。 | 保留加入、叫号、结束时间、队列结果和后续会话，分别统计等待、退出和超时。本版不声称观测到所有未入队的潜在顾客。 |
| 故障多久能修好，哪些时段负荷和电费最高？ | AFDC 强调维修响应、修复时长和可用性；能源部的有序充电资料强调峰值、容量上限和分时电价。 | 保留维修时间轴、故障类别、5 分钟功率、变压器容量及分时价格，为告警与负荷预测提供输入。 |

来源及边界：

1. [AFDC：充电设施运营与维护](https://afdc.energy.gov/fuels/electricity-infrastructure-maintenance-and-operation)。这里只借鉴成本、利用率和维护的分析维度，不套用其中美国收费或维修金额。
2. [Hecht 等：基于德国实际数据的充电站使用与盈利分析](https://arxiv.org/abs/2206.09582)。只借鉴比较维度，不将德国 AC/DC 使用分布当作中国城市真实规律。
3. [Joint Office / ChargeX：客户体验 KPI 实施指南介绍](https://driveelectric.gov/news/kpi-ev-playbook)。本项目采用简化业务事件定义，不声称符合其完整 OCPP 实施规范或某一监管可用率标准。
4. [Chattopadhyay 与 Kar：考虑用户耐心的充电排队研究](https://arxiv.org/abs/2403.06223)。该文的仿真改善幅度不作为本项目预期收益或模型准确率。
5. [美国能源部：车队有序充电](https://www.energy.gov/cmei/femp/managed-ev-charging-federal-fleets)。峰值与容量管理的思路可借鉴；不同国家和用户的需量计费政策不能直接互换。

检索日期：2026-09-12。以下具体公式是本项目的数据分析定义，除明确标明外，并非对这些来源公式的逐条复刻。

## 2. 所有指标共同遵守的口径

- 数据批次：始终限定同一 `dataset_id` / manifest 所指数据目录。不能把原始层、清洗层、样例层相加，也不能将不同随机种子的批次混为一批。
- 时间：`*_at` 用 UTC ISO 8601；日/月/小时业务分组按 `Asia/Shanghai`。时间范围一律采用左闭右开 `[start, end)`。例如 2026-04-01 的本地业务日对应 UTC 前一日 16:00 至当日 16:00。
- 单位：金额字段为整数人民币分，电量为整数 Wh；展示时分别除以 100 和 1,000。`power_kw` 是区间平均功率，不是区间电量，也不是瞬时峰值。
- 观测粒度：`charger_telemetry` 的每条记录描述 `[recorded_at, recorded_at + interval_seconds)`。默认区间 300 秒；不得把同一时刻三台桩的数据当成 15 分钟连续时间。
- 分母：城市和总站比率先累加分子、分母，再相除；不能简单平均各站百分比。分母为 0 时返回 `null`/“无样本”，不能显示为 0% 或 100%。
- 可追溯：一个 charging session 可对应多次支付事件、一条评论等。聚合支付后再关联订单，避免多对多 join 放大电量或订单数。
- 数据质量：错误、缺失、重复行必须先隔离/修正。缺少监测区间时同时报告覆盖率，不用“最后一次在线”填满未知时段。
- 窗口边缘：跨日会话的充电电量按遥测区间分摊，现金按支付发生日，订单数按明确命名的开始日或结束日；三者不能强求同一天相等。
- 本版每个 `charger_id` 表示一个可同时服务一辆车的充电资源。后续若扩展一机多枪，应新增 connector 粒度，不能继续用设备台数当并发车位数。
- 存储：原始数据采用按月分片的 gzip 压缩 CSV；一个分片不是一类新的业务表。读取一个月或全量时都须按 schema 统一类型，避免将文件数当作业务记录数。

## 3. 营收、成本与经营表现

| 指标 | 计算公式与分母 | 主要字段 | 时间及解释 |
| --- | --- | --- | --- |
| 充电服务电量 | `sum(energy_wh) / 1000`，无比率分母 | `charger_telemetry.energy_wh, recorded_at` | 按电量实际发生区间；只汇总一次完整且有效的遥测，不与订单总电量再相加。 |
| 订单应收金额 | `sum(total_fee_cents) / 100` | `charging_sessions` 的费用分项、`ended_at` | 按结束会话归属日，不代表已经收到钱。核对 `电费 + 服务费 + 停车费 - 优惠 = 总额`。 |
| 成功收款 / 成功退款 / 净收款 | 对 `status=SUCCESS` 的 `PAYMENT`、`REFUND` 分别求和；净收款 = 收款 - 退款 | `payments.transaction_type, status, amount_cents, occurred_at` | 现金发生日；`FAILED` 支付不计收入，退款不是负电量。 |
| 平均订单应收 | 结束会话的应收总额 ÷ 同期结束会话数 | `charging_sessions.total_fee_cents, ended_at` | 同一结束日群体；不要用本日收款除以本日新建订单。 |
| 服务费贡献 | `sum(service_fee_cents) / 100`；占比 = 服务费 ÷ 优惠前电费与服务费合计 | `charging_sessions` 费用分项 | 按结束会话；“服务费”不等于净利润。优惠如何分摊需单独约定。 |
| 模拟购电成本 | `sum(grid_cost_cents) / 100` | `charger_telemetry.grid_cost_cents, recorded_at`；会话口径可用 `charging_sessions.grid_cost_cents` | 按遥测区间归属用电日；按结束会话汇总时需另外标明会话口径。两张表是明细与合计关系，不能相加。可用区间购电量和 `tariffs` 复核。 |
| 购电量与充电损耗率 | 购电量=`sum(grid_energy_wh)/1000`；损耗率=`(sum(grid_energy_wh)-sum(energy_wh))/sum(grid_energy_wh)` | `charger_telemetry.grid_energy_wh, energy_wh`，会话表对应合计 | 同一计量范围和时间窗。购电成本按购电量而非车端交付电量计；本版不包含未建模的全场空调、照明等用电，不能命名为真实全站线损率。 |
| 模拟经营贡献 | 同一结束会话群体截至 `as_of` 的净收款 - 该群体购电成本 - 期间日常成本 - 期间维修成本 | `charging_sessions, payments, operating_costs, maintenance_tickets` | 标题注明“截至某日的模拟经营贡献”；不含折旧、税费、资本开支和未建模需量费，不能命名为真实财务净利润。维修成本按 `restored_at` 归属。 |
| 单位电量购电成本 | 对同一群体 `sum(grid_cost_cents) / (sum(energy_wh)/1000)`，单位分/kWh | `charging_sessions` | 不平均每笔订单单价。分母无电量时不可计算。 |
| 优惠使用及成本 | 有 `campaign_id` 的会话数；实际优惠 = `sum(discount_cents)`；使用率 = 优惠会话数 ÷ 全部结束会话数 | `campaigns, charging_sessions.campaign_id, discount_cents` | 按会话结束日和活动有效期对照。`budget_cents` 是预算，不是已经发生的广告投放成本；不能据此声称营销 ROI。 |
| 城市 / 站点排行 | 以净收款、电量、经营贡献分别排序 | 上述结果 + `stations.city_id, site_type` | 显示排行依据、日期、设备数量，避免只按绝对营收误判大站更有效率。 |

分时零售价、服务费、购电价、租金、人工和维修成本均为可重复生成的教学假设。此数据集没有中国真实运营商结算价或地区电力合同，不应用于投资报价。

## 4. 资源利用、负荷与容量

| 指标 | 计算公式与分母 | 主要字段 | 时间及解释 |
| --- | --- | --- | --- |
| 在役充电资源数 | 已投运且在窗口中生效的去重 `charger_id` 数 | `chargers.commissioned_at, station_id` | 快照指标，不把每日资源数累计成设备总数。 |
| 充电时间利用率 | `CHARGING` 秒数 ÷ 同期在役计划开放秒数 | `charger_telemetry.state, interval_seconds`；`chargers.commissioned_at` | 本版模拟站点按 24 小时开放。计划分母由投运时刻和时间窗算，不能只用收到的行数充当计划时长。 |
| 占用时间率 | (`CHARGING` + `RESERVED` + `OCCUPIED`) 秒数 ÷ 同期在役开放秒数 | `charger_telemetry.state` | 同一资源同一时刻状态互斥；停车占位与正在充电分开画。 |
| 充电结束后占位时长 | 每次 `unplugged_at - ended_at` 的均值 / P95 | `charging_sessions` | 按结束会话群体；单位分钟。用于解释“没充电但排不到”的情况，不等于全程停车时长。 |
| 周转量 | 期间开始充电会话数 ÷ 在役资源日数 | `charging_sessions.started_at, chargers.commissioned_at` | 单位次/桩日；分母不是仅产生订单的桩数。 |
| 当前空闲 / 充电 / 预约 / 占用 / 维护 / 离线数 | 对统一快照时刻逐桩状态计数 | `charger_telemetry.state, recorded_at` | 六种状态之和等于该时刻资源数；缺失快照另列未知，不用未来状态补齐。 |
| 站点平均功率 | `sum(energy_wh)/1000 ÷ 窗口小时数` | `charger_telemetry.energy_wh` | 先合计同一站点的全部桩；监测缺失时报告覆盖率和“不完整”。 |
| 5 分钟峰值负荷 | 每站每时刻 `sum(power_kw)` 的最大值 | `charger_telemetry.power_kw, recorded_at` | 只能称“5 分钟区间峰值”，不声称是瞬时电气峰值。 |
| 15 分钟峰值负荷 | 每站连续 3 个完整五分钟区间 `sum(energy_wh) / 1000 / 0.25`，单位 kW，再取最大 | 遥测时间、电量 | 用于教学需量观察；本版未据此收取真实需量电费，缺一个子区间不计算该窗口。 |
| 容量使用率 | 站点区间总功率 ÷ `transformer_kw` | `stations.transformer_kw` + 遥测 | 表示本模拟站的充电负荷与设置容量的比值，不包含场地其他用电负荷。 |
| 峰谷电量占比 | 对同一城市当地小时匹配 `tariffs.period` 后分组电量 ÷ 总电量 | `tariffs.city_id, hour, period` + 遥测 | 不是对峰谷单价作平均。未来若电价变化需增加有效起止时间。 |
| 时段 / 星期热力图 | 按本地小时、星期聚合电量、会话开始数或利用率 | `calendar, charging_sessions, charger_telemetry` | 一张图明确一种量纲。假日/调休日来自官方安排；LOCAL_EXPO 是模拟活动，星期分组不等于法定工作日。 |

## 5. 可靠性、维修与客户体验

| 指标 | 计算公式与分母 | 主要字段 | 时间及解释 |
| --- | --- | --- | --- |
| 监测覆盖率 | 有效且去重的观测秒数 ÷ 计划在役开放秒数 | 遥测与投运时间 | 先展示覆盖率，避免缺数据却报告高可靠性。 |
| 业务可服务时间率 | (`AVAILABLE` + `CHARGING` + `RESERVED` + `OCCUPIED`) 秒数 ÷ 计划在役开放秒数 | `charger_telemetry.state` | 衡量资源未故障/未离线，不代表能立即预约。不是监管认证 uptime；维护与离线分别列出。 |
| 通信在线时间率 | `online=1` 的秒数 ÷ 计划在役开放秒数 | `charger_telemetry.online` | 维护时仍可通信，故在线率可高于业务可服务率。 |
| 到访充电转化率 | `outcome=STARTED` 的请求数 ÷ 已确定最终结局的请求数 | `charging_attempts.outcome, attempted_at, session_id` | 按初次请求日期 cohort；最终结局包括 `STARTED`、`FAILED`、`ABANDONED`、`RESERVATION_CANCELLED`、`RESERVATION_EXPIRED`，仍为 `QUEUED` 的请求单列，不视为失败。每次到访只有一次 attempt，不模拟充电握手重试，所以这不是首次启动成功率。 |
| 请求至开始充电总等待 | 成功请求 `session.started_at - attempt.attempted_at` 的均值 / P95 | `charging_attempts` 关联 `charging_sessions` | `attempted_at` 是初次请求，差值包括排队和预约延迟；不是插枪、鉴权或电气握手耗时。不成功请求的等待需按队列/预约结局单列。 |
| 停止原因分布（本版） | 按 `stop_reason` 分组的已结束会话数 ÷ 全部已结束会话数 | `charging_sessions.stop_reason, ended_at` | 本版只有 `USER_STOPPED`、`DURATION_LIMIT`、`TARGET_REACHED`。没有模拟充电中途故障或通信中断，因此不能把该分布包装为故障中断率或完整 ChargeX session success。 |
| 支付失败率 | `transaction_type=PAYMENT` 且 `status=FAILED` 的事件数 ÷ 全部 `PAYMENT` 事件数（`SUCCESS` 或 `FAILED`） | `payments.status, transaction_type, failure_reason` | 按支付事件发生日，退款不计分母；同一订单的支付重试分别计数。支付重试不能被解释为充电启动重试。 |
| 故障类型分布 / 新增故障数 | 期间 `reported_at` 对应工单数，按 `fault_type/severity` 分组 | `maintenance_tickets` | 本版是空闲资源自动发现故障并建单，不是用户未经核实的报障。工单数不是独立坏桩数；另以去重 `charger_id` 显示受影响资源。 |
| 受理响应时间 | `accepted_at - reported_at` 的均值 / P95 | `maintenance_tickets` | 本版把受理固定安排在下一个 5 分钟步长，结果主要用于时间轴验证，不代表真实服务效率分布。未受理单独统计待办年龄，不算零分钟。 |
| 修复耗时 | `restored_at - work_started_at` 的均值 / P95 | `maintenance_tickets` | 只对已恢复工单；总停用时长另用遥测 `MAINTENANCE` / `OFFLINE` 区间。本版自动发现故障即停用，但该假设不适用于一期用户提交报障待核实的流程。 |
| 未解决积压及年龄 | 在 `as_of` 前报告且未在该时点恢复的工单数；年龄=`as_of-reported_at` | 工单时间及 `maintenance_events` | 历史回放必须依据事件时刻，不能用最终状态穿越到过去。 |
| 排队转化率 | 最终关联成功会话的队列条目数 ÷ 已结束的队列条目数 | `queue_entries.status, session_id, resolved_at` | 同一加入日期 cohort，截至 as_of 的已结局样本；还在排队的单独显示。 |
| 排队退出率 / 叫号未确认率 | 各对应结局条目数 ÷ 已结束队列条目数；叫号后超时也可另除以已结束的已叫号条目数 | `queue_entries.status, called_at` | 两种分母的指标不同，标题必须写清楚。未入队就离开的潜在用户不在本版分母。 |
| 等待时长 | 被叫号者 `called_at-joined_at` 的均值 / P95；退出者 `resolved_at-joined_at` 单列 | `queue_entries` | 不混成“所有人的成功等待时间”，同时显示各群体样本数。 |
| 预约履约 / 取消 / 过期率 | 各最终结局的预约数 ÷ 已结束预约数 | `reservations.status, created_at, resolved_at, expires_at` | 按预约创建 cohort，截至 as_of；仍待履约的预约不当作取消。 |
| 评分与低分原因 | `avg(rating)`；低分率=`rating<=2` 的评论数 ÷ 评论数 | `reviews.rating, issue_type, created_at` | 1–5 分教学量表；只反映评论人群，不把无评论订单当五星。 |
| 活跃 / 复购用户 | 期间有成功充电会话的去重用户；复购率=期间有至少 2 次会话用户 ÷ 活跃用户 | `charging_sessions.user_id, started_at` | 这是“窗口内重复使用率”，不是次月留存率；留存须另按完整月 cohort 计算。 |

## 6. 让数据能产生有解释力的结果

23 类数据覆盖基础维度、商业行为、运行状态、维修、评价、外部场景、网外能量账以及脏数据标签。生成逻辑应维持下列关系；具体数值参数以配置和代码为准。

1. 不同城市、站点类型和工作日时段有不同到达需求；不是每个站每天完全一样，也不是所有字段独立随机。
2. 用户、车辆、请求、会话、支付有外键。一次到访记录一次 attempt，请求未成功可以没有会话；不模拟同一次到访的充电握手重试。失败支付可以重试；有退款才有退款记录。支付与充电请求属于不同事件链。
3. 桩状态决定是否能开始充电；同一资源不能同时服务两辆车。SOC、车辆电池容量、车辆最大充电功率共同限制模拟过程。
4. 充电功率与区间电量相容，会话交付电量和购电量可由遥测重算，累计电表单调。住宅 AC 可隔夜停留、办公 AC 可充满后占位；供电与车位占用分开统计。
5. 仅在资源空闲、没有充电会话也没有预约占用时，自动检测随机故障并立即停用。维修事件构成时间轴，期间暂停接单，恢复后可重新服务。这里的 `reported_at` 是自动故障建单时刻，不是一期用户点击“报障”的时刻；不能解释为用户报障后不经管理员核实就停用。此版本不模拟故障打断正在充电的会话。
6. 天气使用带署名的 ERA5 再分析（自定义日期超范围时明确模拟回退），节假日日期引用官方日历。它们影响到访、出行或功率的强度是教学设定，并非真实因果估计；LOCAL_EXPO 是模拟活动。
7. 脏数据用于演示 Spark 清洗，保留注入清单和清洗报告。标注表不能作为预测特征，也不能把清洗后的正确值直接作为输入给模型。
8. `battery_samples` 仅在正在充电时产生，不为每个空闲桩伪造电池。电池样本数量不能作为监测全站在线率的分母；充电电流统一约定为非负。部分故障标签用于离线算法验收，不代表已建立真实电池故障诊断系统。
9. `vehicle_energy_intervals` 跟踪车在平台外的净能量变化，允许外部补能但不计本平台收入，解决“每次独立重设SOC”的失真。跨会话的能量账必须可核对；它不是完整真实车辆行程。

当前 `anomaly_labels` 包含 `POWER_DERATING`（降功率）、`EARLY_STOP`（计划少充，通常以 `USER_STOPPED` 结束；若先达到停留或批次上限则为 `DURATION_LIMIT`）、`THERMAL_STRESS`（温度升高）。它们是教学注入场景，不是自动断电、硬件损坏或维修触发记录。温度场景不会触发保护停机，评论也只覆盖有会话的部分用户。要扩展“故障中断率、保护响应时间、首次充电重试成功率”，必须先扩展事件模型再生成数据，不能在本批数据中假定这些事件已存在。

其他当前版本边界：

- 所有会话目标模式为 `ENERGY`，不能用这批数据展示金额/时长目标之间的行为差异。`DURATION_LIMIT` 是模拟会话时长上限，不代表用户选择了按时长目标。
- 站点变压器容量目前统一为 360 kW；一站三台设备的最大交付功率合计至多 187 kW，未产生真实意义的变压器越限。可以展示负荷曲线和容量比例，不能演示不存在的越限事件。
- v2 按用户分群、常用站型及活跃度设置到访/选桩偏好；会员和来源仍只提供分组维度。优惠活动只改变结算，不改变需求概率，因此不能据此声称“会员留存提升”或“投放带来因果增量”。
- 维修严重程度当前均为 `MEDIUM`，受理和开始工作采用固定时间步；故障类型和修复时长有变化。不要把固定列包装成已经覆盖多种严重等级的样本。
- Python 参考日汇总的 `completed_sessions` 指已结束的充电会话数量，包含 `WAITING_PAYMENT`，不是 `status=COMPLETED` 的已支付订单数。页面宜标为“结束会话数”，已支付订单应另从成功支付去重计算。

## 7. 大屏与预测的落地顺序

第一屏优先放电量、净收款、会话数、可服务率、平均等待，以及五城市地图、趋势、状态分布、站点排行。第二屏放成本、峰谷时段、维修时间轴、支付失败与到访未充电原因、排队结果和评分分布。数据处理页展示原始/有效/隔离行数与错误种类。

预测训练从小时级站点数据起步：未来 1/6/24 小时负荷、时点空闲资源数。可用历史滞后量、过去滚动量、城市/站点类型及已知日历特征。不要把未来结束会话费用、未来实际天气、未来维修恢复时间、异常标签或目标时间段真实电量作为输入。训练、验证、测试必须按时间分开，跨切分点的预测标签需隔离；仅在模拟数据上评估的模型必须明确标注“模拟数据测试表现”。

当前数据可支持这些分析，不等于已提供深度学习预测接口。后续实现 LSTM、随机森林比较和 Vue 页面时，应复用这里的字段、单位与时间规则。
