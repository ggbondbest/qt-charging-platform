# AI参谋的运营分析方法

本文维护参谋可以引用的分析方法，知识片段在 `data_analysis/ml/advisor/knowledge.py` 中对应保存。方法本身不是某次查询的业务结果：事实、数字、比较对象和日期必须来自本轮检索的发布聚合；全部充电业务数据仍是教学模拟。

## 1. 完整等长期间对比

当前窗口为 `[start, end)`，紧邻前期为 `[start − (end − start), start)`，都按北京时间业务日计算，并保持城市、站点筛选不变。只有整个前期在同一发布批次内时才进行比较；不足时明确说明，不缩短前期、不填零，也不拿其他批次代替。该受控前期不允许正文指定任意其他日期来改写页面范围。

电量和净收款给出两期值、绝对差及相对变化：

- 绝对差 = 当前 − 前期。
- 相对变化 = `(当前 − 前期) / abs(前期) × 100`。前期为零、缺测或没有有效分母时不计算。
- 利用率和成功率以百分数表示时，当前减前期的单位是百分点；它不是相对增长百分比。

净收款可能因现金退款而为负。此时须同时展示前期金额、当前金额、绝对差和明确命名的相对变化，不称为利润增长率；净收款仍是成功收款减成功退款。金额与电量的显示换算由数据层完成，模型不自行重算。

两个窗口等长不代表工作日、节假日、站型、人群或遥测覆盖相同。先核对可比条件，再描述变化；前后变化本身不能证明某项措施有效。字段和公式以 [分析模块](../ml/advisor/analysis.py)、[既有指标口径](operator_metrics.md) 为准。

## 2. 供需与失败原因分解

先区分需求规模、资源使用和服务过程。尝试量描述已观测的充电请求，成功率描述最终开始充电的比例，充电利用率来自完整遥测小时；不能把它们当成同一个指标。

查看失败原因前三项时，同时读原因数量及其占全部未成功尝试的比例。再按入口、站型和小时对照样本与成功率，形成条件式排查方向：

- 无可用桩较多时，可复核接口是否匹配、预约占用和充后占位；需要对应业务或现场记录确认。
- 等待离队较多时，可核实等待信息、队列规则和用户可预期的等待过程。
- 叫号未确认较多时，可核实通知触达与确认流程；当前聚合不能证明通知系统存在故障。

低利用率也可能与需求、时段组合或观测覆盖有关，不能直接认定设备故障。最高尝试量的站型小时受站数和范围长度影响，不是每站到达率，也不是实时队长。不同事件归属日期和小时的差异见 [多维分析口径](advanced_analytics.md)。

## 3. 行动与验证指标

“怎么改进”“给建议”“运营策略”类问题应先明确目标，再用本轮证据定位一个可复核问题。一个可审阅的建议应包含：对应证据、待验证假设、具体措施、观察范围、判断指标与尚缺条件。

可以把核实叫号信息、检查排队流程、复核占位规则作为需要进一步确认的措施。新增资源、调整价格或营销方案还需要相应成本与业务资料，不应直接由一个聚合值推出。

观察指标应与目标一致，也要覆盖可能变差的方面：成功率和尝试样本、平均等待和有效等待样本、失败原因构成、完整小时利用率、净收款与退款。保留完整等长窗口及可比较的对照站；避免只选择改善的一项来宣称成功。

没有措施实施时间、必要业务记录或完整观察窗口时，先补齐验证条件。参谋提出建议不等于已执行动作，也不表示已经产生运营效果。

## 4. 群体构成与辛普森偏差

总体比率和均值不仅取决于各组表现，也取决于各组的样本权重。城市、站型、小时或用户类型的构成变化，可能使总体趋势与同类群体内趋势不同，甚至方向相反。这类方向反转常称辛普森偏差或辛普森悖论；本文解释一种风险，不宣称当前数据已经出现它。

应并列核对同类群体内的指标、有效样本以及群体构成。总体比率必须合计分子分母后再相除，不能平均各组百分比。当前证据没有完成的分层、重新加权或因果调整，不能由模型宣称已经完成。

补能行为按会话或可观察间隔统计。高频用户会贡献更多记录，群体会话占比不是去重用户占比；平均补能间隔也不应取倒数来伪造人均充电频次。缺少组内证据时，应保留总体描述的限制。

## 5. 样本、对照与优先级

“优先处理哪里”“先做什么”必须写明选取依据。当前确定性模块从至少30次尝试且成功率有效的电站中，按成功率由低到高选择最多三座关注站；对照来自另一座达到门槛的站，优先选与首座关注站同站型且成功率较高者。

不足两个可比站时明确没有独立对照；小样本不进入优先列表。30次只是展示门槛，不能视为统计显著性或可靠性保证。查看候选时还须并列核对尝试数、等待和利用率；该列表不是设备故障清单或综合优劣排名。

对照站没有随机匹配，供给、时段和用户构成可能不同。它用于提出需要核实的差异，不用于把全部差距归因于某项运营策略。证据预算按完整组分配，未列出的站点或群体不等于没有业务记录。

## 6. 合理建议与收益边界

回答应区分“已观察事实”“待核实解释”“可选择的行动”。合理建议与当前证据建立联系，并说明需要什么观察才能判断是否改善；证据不足时可以给方法框架，但不能编造当前排名、数字或已经完成的行动。

调费、营销、扩容和接口改造的效果，需要额外成本、需求与实施后观察。当前聚合不能保证挽回订单、增加利润或达到某个设备故障概率。模型分数和模拟数据关联也不能直接推广成真实经营效果。

## 7. 检索与提示设计的参考边界

本项目先从已发布结构化聚合检索事实，再从本地维护的知识片段中做关键词/BM25排序，最多取四段；“不能”“如何”等通用问句词不单独贡献匹配分数，主题标签只能调整实际匹配的排序，不能让无关词自动命中。维护本文时应同步修改知识片段及检索回归测试。

本次问题的真实词汇匹配优先，最近对话只补剩余知识空位并去重，避免长历史答复压过“怎么改进”等短追问。历史会清除可识别的旧引用标记，但保留的文字和数字仍不是新证据；总结历史分析时必须重新读取当前范围聚合。
引用ID仅在本轮有效。精确中文/组引用可以调整显示格式，网页来源列表据正文实际ID形成；不得通过猜ID、改数值或把仅列在数组中的来源补进正文来制造有据回答。

[LangChain 的 Retrieval 文档](https://docs.langchain.com/oss/python/deepagents/retrieval)说明，已有 SQL 数据库或其他知识库可以通过查询取得上下文，不必为了 RAG 重新建立向量库。这里借鉴的是检索后生成及结果校验的结构，不能据此宣称本项目已使用其框架或获得特定准确率。

[Anthropic 的提示实践文档](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)建议明确任务、上下文、输出约束和有代表性的例子。它面向 Claude；将这些原则用于本项目的 AIPing 模型属于工程选择，效果必须以本项目问题、范围一致性、引用有效性、答案质量和响应耗时实测，不能照搬其他模型的效果数字。参考页面核对日期：2026-09-16。
