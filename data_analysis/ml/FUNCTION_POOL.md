## 3. 定案:3 核心 + 3 创新 + 2 预留

**核心(已交付,只做收尾)**:① 负荷与空闲桩预测(+G/H:区间带、漂移报告、SHAP);
② 异常诊断(+因果探针→v6 补齐 EARLY_STOP/DERATING,+severity);③ 用户流失风控。

**创新(按 A→C→B 顺序新开工)**:
1. **A 反事实运营模拟器**:到访/负荷响应函数(价格弹性用 campaigns 自然实验实测)→
   "加桩/调价/关站 → 新负荷曲线、新等待时长、流量再分配"。预测走向决策的闭环。
2. **C AI 运营参谋**:Claude API + 只读工具(冻结工件/预警表/模型卡/A 的模拟结果),
   回答"为什么 A 站昨天负荷高""这批告警可信吗";答案必须引用来源文件,无据即说无据。
3. **B 设备健康度 + 预测性维护**:charger×周面板,标签=未来窗口维修(maintenance_tickets),
   新监督线 = 新 model_id + TEST 一次首盲。RUL 上限如实写成"下次故障间隔预测"。

**预留(写进需求分析,本期不做)**:① E 变压器过载 + 全网功率分配(依赖 A 的负荷;
执行属客户端);② L 新站选址(需人流/POI 外部数据,现数据只够覆盖/缺口分析)。

**答辩主线**:预测(核心①)→ 诊断(核心②③)→ 决策(A/B)→ 解释(C/H)——
正好覆盖验收规格(5)的"预测 / 诊断 / 调度 / 风控"四口径,外加一层生成式 AI。

## 4. 纪律(不破)

- 一切带"精度"宣称的新线:B 与 D(v6 同理)= 新 model_id + TEST 一次首盲,先例照 v1-v5;
  A/C/G/H 属工具与解释层,不产盲评分数,不得伪造"准确率"。
- 未来维修时刻、预约履约、未来实际天气不得当已知特征(契约红线原样适用);
  maintenance_tickets 只做未来窗口标签,队列/告警特征只用预测起点之前。
- datasets/ 只读;新实验用合成批次放独立目录,不改既有包。
- 表述上限:"模拟数据测试结果"。
