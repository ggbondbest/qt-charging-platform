# 用户未回访风险（交付版 v3）

以 **2026-05-15 上海时间零点**为历史观察点，判断用户未来 14 天是否没有任何充电请求。
这是管理者的历史用户风险筛选，不是实时预测、永久流失判断或发券收益预测。

## 使用与对接

```bash
python -m data_analysis.ml.insights train
python -m data_analysis.ml.insights report
python -m unittest data_analysis.tests.test_ml_insights_delivery
```

统一训练、报告及推理见 `ml/insights.py`。`InsightsService.list_churn()` 默认展示未参与拟合的 TEST 用户；
`predict_user(id)` 可以检查本批已有的模拟用户。所有结果带模型 ID、历史观察时间、数据批次和模拟数据标记。
新注册的体验账号与历史 6,000 用户没有映射，不会伪造其历史特征。

## 修复的口径

- CLEAN 时间戳按 UTC 解释，业务观察时间对应 `2026-05-14T16:00:00Z`。
- 14/30/60/90 天均以观察点为锚，`started_90` 不再混入全历史。
- 会话只有在观察点前已结束，才使用其最终电量和费用；金额从分正确转换为元。
- 排队加入数使用已知加入时间，最终弃队状态须已在观察点前解决。
- 队列可能在观察后才开始充电，不能把最终 STARTED 状态提前当作成功记录。
- 排除观察点后注册用户；计数缺失补零，无法计算的比例/最近访问时间保持缺失。
- 不再复用无源指纹的旧特征缓存。数据、模型、报告指纹全部绑定，验证完成后才反序列化。
- 不使用旧版 `class_weight=balanced`；仍将输出称为**风险排序分**，未宣称概率校准。

## 模型与实际结果

`hgb-churn-asof-v3`：HistGradientBoostingClassifier，29 个固定特征，用户哈希切分 70/15/15。
同一用户不会跨训练、验证和测试；但这是单个历史观察点，不能代替未来时间段现场验证。

| TEST（935 位用户） | 模型 | 仅最近访问天数 |
| --- | ---: | ---: |
| AUC | 0.7423 | 0.6046 |
| PR-AUC | 0.3316 | 0.2727 |
| 前10%风险人群提升倍数 | 2.369 | 1.921 |

高/中/低风险按 TRAIN 风险分 p90/p70 固定阈值划分，不代表某种干预一定有效。
