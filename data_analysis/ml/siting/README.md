# 新站选址线（`ml/siting/`·由第九线预留项转实做）

> **口径声明**：本线全部指标为**模拟数据**测试结果（第二阶段发布批次
> `analytics-298aa3ee1401461fb06ea2bb96930dcf`），不代表真实运营数据表现。本线**未新增任何数据**——
> 需求强度、弃队代理、坐标全是对发布批次 clean 表（`charging_sessions` / `charger_telemetry` /
> `queue_entries` / `stations`）的只读确定性聚合（25 站 × 180 个**业务日**，业务日 = UTC+8）。

## 一句话结论

**"用邻居站的观测需求外推新站的空间需求"这条选址前提，在本批拿不到正证据；但本批也不是"没有规律"——
可外推的规律在"建什么类型"（`site_type` 的城内份额 LOSO Spearman = +0.897），不在"建在哪"。**
本线交付的是**真工具链 + 可复算的分层结论**，不是一个号称能选址的模型。

## 为什么"LOSO 为负"这句话本身不含信息量（本线最重要的一条纪律）

仿真把**每个城市的需求总量近似恒定**（归一化离散 0.0427）地在其 **5 个站**之间切分。于是一城之内

```
Σ_{j≠i} d_j = T_c − d_i      （每城恰 5 站 ⇒ "其余站之和"与"本站"是定义式反相关）
```

**任何**用其余站需求构造的预测器——带不带坐标都一样——都**必然**反预测被藏站。所以"场模型 LOSO 为负"
不能当结论用；把它当结论用就是本线早期版本的错误。同理，`cityMean`（只用"哪个城"）与机制诊断里的
"其余站之和"**只差一个常数**（除 4 不改秩），二者实测一字不差（**−0.8786** vs **−0.8786**）——
它们是**同一条证据**，不是两条独立确认数。产物里把这条关系明写出来（`baselines.sameAlgebraAsMechanism`）。

## 有信息量的两条

### (1) 正确的零线是"城内置换"，而场模型落在它下面

"没有空间信号"应有的对照，是**保住每城总量与 5 站零和、只打乱"谁站在哪"**（城内混洗需求，200 次重抽，
seed 20260915）。注意这条零线**本身不在 0**：本批它随半径为 +0.228 / +0.223 / +0.202 / +0.172 / +0.128
（弱正——打乱站位后，场的"中心位置天然吸得多"这类位置级效应仍能蒙到一点正相关）。判断场的读数
一律以这条带为准，**不是**以 0 为准。

| 吸引半径 km | 场 Spearman | 名义 p | 城内置换零线均值 | 零线 [p5,p95] | P(零线≤观察) | 全局置换零线均值 |
| ---: | ---: | ---: | ---: | --- | ---: | ---: |
| 2.0 | −0.524 | 0.007 | +0.228 | [−0.020, +0.476] | 0.000 | +0.183 |
| 3.0 | −0.522 | 0.007 | +0.223 | [−0.060, +0.450] | 0.000 | +0.191 |
| 5.0 | −0.589 | 0.002 | +0.202 | [−0.087, +0.426] | 0.000 | +0.163 |
| 8.0 | −0.677 | <0.001 | +0.172 | [−0.187, +0.466] | 0.000 | +0.139 |
| 12.0 | **−0.789** | <0.001 | +0.128 | [−0.233, +0.464] | 0.000 | +0.092 |

全部半径上观察值都**落在城内置换零线的 p5 之下**（200 次重抽里没有一个 ≤ 观察值 ⇒ 经验 p ≤ 0.005）——
这才是"比无信号更糟"的正经读法。全局置换那一列（+0.183 起）是旧版 `random` 基线的正确版本，
它打破城市零和结构，对本模型**是错的对照**，留在表里只为说明"为什么不能用它"。

读数的来源可拆两半：**短半径**读到的是本批真实的**倒置邻接结构**——最近邻站需求 vs 本站 Spearman
= **−0.663**，远负于"随机切分"的理论地板 −1/(k−1) = **−0.25**（k=5）。也就是说城内**不是**"无空间梯度"
（早期版本把"站间距近于均匀"读成"没有人流梯度"，是错的：均匀间距不等于无结构），而是仿真给近邻配了
互补份额的**倒置梯度**。**长半径**则被上面那条零和代数接管：读数总体走弱（−0.524 → −0.789），
但**非严格单调**（r=2→3km 有一小步回升 −0.524→−0.522）；产物里 `strictlyWorsensWithRadius=false` /
`weakensWithRadiusOverall=true` 两个标志位分开记，正文措辞由实测生成，不写死。

统计边界也要写进产物：n=25 站的截面，且 25 个 LOSO 预测共享同一批 24 个需求值（彼此强相关），
所以 scipy 的 p 值**只是名义显著性**（`pValueCaveat` 随每个读数一起落盘）。

### (2) 同一批数据里，`site_type` 是真能外推的

每城每型恰一站 ⇒ 同类型留一只能**跨城池化**（被藏站不参与任何一格）。以"城内归一需求份额"为目标：
LOSO Spearman = **+0.8969**（n=25）。类型均值份额：TRANSIT 0.331 · SHOPPING 0.241 · OFFICE 0.166 ·
CAMPUS 0.141 · RESIDENTIAL 0.122。这不是选址（where）证据，是建型（what）证据——放在这里是为了把
"本批没有可学规律"这句话**限定到它该被限定的范围**。

## 需求口径本身也不干净

* 强度有两种真实口径：**会话数**与**该站该 tick 在充的 5 分钟充电 tick 数**（不是"充电分钟"），
  两者站级 Spearman 只有 **0.469**——连"需求"都没有一把干净的尺子。本线主口径取会话数，
  并在 `mechanism.demandTwoViewsSpearman` 里把分歧钉住。
* 弃队代理 `demand_incl_unmet = 会话数 + ABANDONED`（网络计 10,143）里，**476 条（4.69%）**弃队在 24h 内
  同人同站又开成了会话 → 这部分是**双计**；另有 `CALL_EXPIRED` **4,037** 条同属未满足需求但**未并入**
  （未做敏感性分析）。两处都写进 `backtest.json.unmetProxyCaveats`，不留到注释里。

## 双向单元测试：负结果不是模型 bug

`siting/tests/test_siting.py` 用方向相反的合成用例把这件事钉死（42 个 `unittest` 方法）：

* **zero-sum 合成**（每城总量恒定、城内切分）→ `field`、`cityMean`、最近邻都为负（复现真实批结论为回归）；
* **gradient 合成**（3×3 晶格、城内确有连续梯度）→ `field` 为正（Spearman > 0.8），而**同一份数据**上
  那把丢掉坐标的"城均"打分变成常数 ⇒ `spearman is None`（秩相关无定义，不是 0）；
* **倒置结构合成**（每城 4 站、紧密互补对）→ ρ = −1，深于地板 −1/(4−1) ⇒ 机制诊断会报"倒置梯度"而不是
  "无梯度"。

即：**场模型在有可外推的空间信号时是对的方向**；真实批为负是**数据里没有可从邻居推断的正向信号**，
不是代码写错。

## 机会打分（工具，`NOT-BACKTEST-VALIDATED`）

`score.py` 在每城站点包围盒外扩 ±0.08°（≈±9km）内以 0.02°（≈2.2km）撒网格 → **840** 个候选点，
按 `opportunity = absorb ×（1 − coverage）` 排序，按城各取 top-5、且**只保留离最近现有站 >2km** 的点
（小于它就是"在既有站旁边加建"，不是新地块），入榜 **25** 行。吸引半径取 r=3km（城内站距 p50≈6.6km、
站最近邻均值≈4.2km 的半格量级），需求口径叠加 ABANDONED 弃队。

引用别人的结论就得读得到那份结论：`score.py` **先读** `backtest.json`，缺文件 → `FileNotFoundError`，
批次号不符或缺 r=3km 读数 → `BatchMismatch`，都不落盘。读到的数字原样写进 CSV **每一行**
（`model_status=NOT-BACKTEST-VALIDATED`、`backtest_field_spearman=−0.522`、
`backtest_incity_null_spearman=+0.2234`）与 `score_summary.json.backtestReadback`——CSV 会被单独拷走、
单独打开，状态标记不能只活在 JSON 侧文件里。在这些排序被上面的 LOSO 结论解决之前，它们是
**机械演示**，不构成可信选址建议。

## 复现（仓库根目录，`PYTHONPATH` 指向仓库根）

```
$env:PYTHONPATH = "C:\Users\admin\qt-charging-platform"
python -m data_analysis.ml.siting.backtest     # LOSO 盲测 + 两种置换零线 + 基线 + 机制诊断 + site_type

```

> 为什么用 `unittest` 而不是 `pytest`：仓库 CI 跑的是 `python -m unittest discover -s data_analysis/tests`
> 与显式模块清单，**pytest 不在声明依赖里**——`pytest` 风格的测试在这个仓库里等于没跑。

产物落在 gitignored 的 `data_analysis/outputs/ml_siting/`（`backtest.{json,md}`、`score_summary.json`、
`candidate_opportunities.csv`；`O_EXCL` 独占写，入口 `require_empty_run_dir` 拒绝就地改写，`score` 用
`extra_allowed` 放行 backtest 两份产物）。两份 JSON 产物都带**输入表内容摘要**（`stations` /
`charging_sessions` / `charger_telemetry` / `queue_entries` 的 sha256，`backtest.md` 里也列一份）
——换表即产物失效。

## 已知不足

- **无外生需求面**：仓库没有人流/POI/交通量任何一张表，需求只能从被服务点反推。这是**文件清单事实**，
  不需要回测来证明，本回测也没为它增加证据；真实选址需接入外部需求面。
- **空间外推未通过**：场模型读数在全部半径上低于城内置换零线，因此 `score.py` 的排序不可用于决策。
  注意这**不等于**"本批无空间结构"——实测是**倒置**结构（最近邻 −0.663 vs 地板 −0.25）。
- **n=25 截面 + LOSO 共享数据** ⇒ p 值只是名义显著性；置换零线是 200 次重抽的经验带，非解析检验。
- **需求口径不唯一**：会话数 vs 充电 tick 秩相关仅 0.469；弃队代理含 4.69% 双计、`CALL_EXPIRED` 未并入。
  换口径（按时段/用户画像）可能改变排序，本线只钉主口径并披露分歧。
- 契约边界：本线只读发布批 clean 表、**不新增数据、不进 `delivery/`、不动 `contracts/`**；若日后接入
  外生数据需另立数据源批次，届时本线按 `verify_batch` 换绑重跑。
